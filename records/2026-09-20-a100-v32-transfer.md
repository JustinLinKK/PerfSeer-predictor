# ABA A100 V3.2 teacher transfer campaign

## Scope and immutable inputs

- Source corpus: `/data1/yufan/perfseer_v32_a100_bs_training_20260908/ready_for_train` on ABA.
- Target contract: twelve physical labels, six physical output heads, and Ground Truth (GT) accuracy reported separately within 5 percent and within 10 percent relative error.
- Selection: exact deterministic 25 percent joint-stratified subset, preserving source train/validation/test membership: 9,003 / 1,136 / 1,066 rows (11,205 total). It includes 1,228 rows whose detailed provenance includes the `a10_bs` archive.
- Parent: V3.2 epoch-26 teacher, SHA-256 `5792c12088988dfc514d76a0a4d0a7ff4f7155c26dea529486194066cc656a42`.

## Safety and execution

- GPU 0 is ABA's `NVIDIA A100 80GB PCIe`. GPU 1 has a foreign VLLM engine and is not touched.
- Every label is measured only while GPU 0 has no foreign compute process. If another process appears on GPU 0, labeling fails safe and retains completed labels.
- The controller writes one raw telemetry attempt and one graph trace per selected configuration. Transfer is blocked until every attempt has the correct campaign identity, graph hash, both train/inference telemetry, and twelve finite physical labels.

## Transfer design

- Freeze graph encoders and message-passing blocks.
- Adapt only `phase_encoder`, `phase_fusion`, `phase_fusion_norm`, and all six `prediction_heads`.
- Use the exact V3.2 parent normalization and train for at most 30 epochs with validation every two epochs. Keep the best checkpoint using the V3.2 validation selection key and then evaluate the held-out test split.

## Verification completed so far

- Local controller tests: 6 passed.
- Python compilation: passed locally and on ABA.
- Label campaign started on ABA GPU 0 with a resumable progress log; it is intentionally not interrupted.
- A remote supervisor waits for the labeler's explicit complete status, reruns label verification, materializes the A100-only dataset, and launches the guarded transfer stage. A non-complete labeler exit is reported as failure rather than retried against a possibly contended GPU.
- The supervisor now handles a labeler exit caused specifically by GPU 0 contention: it waits until no foreign GPU 0 process exists, then resumes the retained campaign. Any other labeler error remains a hard failure for investigation rather than being retried blindly.
- A periodic heartbeat independently monitors the ABA campaign and remains quiet unless it observes a failure, contention, verified stage transition, validation result, or completion.
- Live audit at the first 100 completed measurements: all 100 had twelve finite target values; the only non-complete attempt was the active measurement in progress.
- Exact executable-workload deduplication reduced the 11,205 selected aliases to 1,132 distinct A100 measurements. The proof key is the exact pair of `anchor_id` and full training configuration, the only row-dependent values consumed by the profiler. Each remaining alias records the measured configuration ID and immutable attempt hash it reuses.
- Structural audit: every one of the 1,132 workload groups has exactly one source paired-graph SHA-256. A sampled duplicate pair also had identical `NODE_SPECS`, `EDGE_SPECS`, `INPUT_SPECS`, and `TRAINING_CONFIG`; deduplication therefore does not collapse distinct predictor inputs.
- A100 label completion and verification: 11,205 / 11,205 selected rows passed with the planned 9,003 / 1,136 / 1,066 train / validation / test split and the twelve-label contract.
- ABA uses PyTorch 2.7.1 with CUDA 12.6, which does not provide `torch.optim.Muon`.  The V3.2 source now selects Muon when it is present and otherwise uses AdamW with the same deterministic matrix-parameter partition and schedule; the fallback was exercised locally, controller tests passed (7), and the updated source compiled on ABA before the guarded transfer restart.
- Pair-input correction: the available historic V3.2 paired corpus omits all 1,228 selected `a10_bs` rows and assigns at least some shared sample IDs to different splits.  It is therefore not safe to use as a transfer-input source.  The transfer dataset now derives one strict V3.2 paired graph per exact A100 workload from that workload's retained strict A100 training trace plus a replay-verified CPU inference trace.  Every alias in a workload group uses the same graph, and the controller rejects any workload group that crosses the preserved source split.
